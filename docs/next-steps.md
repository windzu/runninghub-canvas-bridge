# Next Steps

## Immediate Validation

1. Run syntax checks:

   `node --check server/server.mjs`

2. Start the server:

   `node server/server.mjs`

3. Load the unpacked extension in Chrome:

   `/Users/wind/Projects/runninghub-canvas-bridge/extension`

4. Refresh the test canvas:

   `https://rhtv.runninghub.cn/projects/canvas/2058411776657580034`

5. Confirm `bridge.installed` appears:

   `curl http://127.0.0.1:8765/events`

6. Confirm command round trip:

   `curl -X POST http://127.0.0.1:8765/command -H 'Content-Type: application/json' -d '{"type":"graph.snapshot"}'`

## First API Experiments

Use the `api.post` command from Codex/local shell so the request runs inside the page context.

Recommended first target:

- `/canvas/getCanvasDetail`

Goal:

- learn the exact request body
- learn response shape
- identify persisted workflow fields

Recommended second target:

- `/canvas/workflow/list`

Goal:

- find workflow ids and relation to canvas id

Recommended third target:

- `/canvas/openclaw/chat`

Goal:

- capture raw request/response/SSE chunks generated by the official Agent UI
- reconstruct the minimum body needed for external Agent control

## Milestone 1

Codex can read current canvas graph without using mouse operations.

Deliverables:

- stable `graph.snapshot`
- stable `getCanvasDetail` command wrapper
- documented response schema

## Milestone 2

Codex can create a two-node text workflow and one edge through API/tool-level calls.

Deliverables:

- command that accepts a minimal workflow config
- persisted canvas update after refresh
- no model generation
- no RH coin consumption

## Milestone 3

Codex can call or emulate RunningHub Agent tool calls.

Deliverables:

- capture `/canvas/openclaw/chat` raw request/response
- parse tool calls or `canvas-command`
- implement local wrappers for:
  - `create_workflow`
  - `update_node_params`
  - `run_node`
  - `delete_node`

## Milestone 4

Package as a local Codex integration.

Options:

- MCP server exposing RunningHub canvas tools.
- Codex plugin wrapping the bridge.
- CLI-first tool with JSON commands.

Preferred direction:

MCP server, because the eventual target is direct Agent tool use rather than manual shell commands.

## Risks

- RunningHub can change internal APIs without notice.
- Some endpoints may require anti-CSRF headers or dynamic request fields.
- `page.eval` is powerful and should never be exposed remotely.
- Streaming Agent responses may need careful SSE parsing.
- Direct workflow save may need frontend-generated layout/group metadata, not just logical nodes and edges.
